## Mathematics

Inline math sets in the run of text, so a claim about $H^n(X;\mathbb{Z})$ or a stray $\gamma < 1$ keeps its line spacing rather than shoving the paragraph apart.

Display math gets its own line and centres. Stokes' theorem, which is the observation that made me care about any of this:

$$
\int_M d\omega = \int_{\partial M} \omega
$$

Multi-line derivations use an aligned environment, breaking at the relation so the equals signs stack:

$$
\begin{aligned}
\|T v - T w\|_\infty
&= \max_s \Big| \max_a \big[ R(s,a) + \gamma \textstyle\sum_{s'} P(s'|s,a) v(s') \big] - \max_a \big[ \cdots w(s') \big] \Big| \\
&\le \gamma \max_s \max_a \sum_{s'} P(s' \mid s,a) \, \big| v(s') - w(s') \big| \\
&\le \gamma \, \|v - w\|_\infty
\end{aligned}
$$

Everything is rendered by KaTeX at build time, so there is no layout shift while a script decides what the page looks like, and the math is still math if the JavaScript never arrives.

## Code

Five languages, because those are the ones I reach for.

Haskell, the `Traversable` instance for a binary tree, which is the shortest honest example of why `Applicative` is the right abstraction for the job:

```haskell
data Tree a = Leaf | Node (Tree a) a (Tree a)

instance Functor Tree where
  fmap _ Leaf = Leaf
  fmap f (Node l x r) = Node (fmap f l) (f x) (fmap f r)

instance Foldable Tree where
  foldMap _ Leaf = mempty
  foldMap f (Node l x r) = foldMap f l <> f x <> foldMap f r

instance Traversable Tree where
  traverse _ Leaf = pure Leaf
  traverse f (Node l x r) = Node <$> traverse f l <*> f x <*> traverse f r
```

def value_iteration(states, actions, backup, eps=1e-6):
    v = {s: 0.0 for s in states}
    while True:
        nxt = {s: max(backup(s, a, v) for a in actions(s)) for s in states}
        if max(abs(nxt[s] - v[s]) for s in states) < eps:

## Inline marks and footnotes

Text can be **strong**, *emphasised*, ~~struck through~~, or set as inline `code`. Keys are marked up as <kbd>⌘</kbd> + <kbd>K</kbd> so they read as keys and not as code.

Footnotes hang at the bottom of the page and link both ways[^1]. They are the right place for an aside that would derail a sentence[^2].

[^1]: Clicking the marker takes you here; clicking the arrow takes you back to where you were reading.

[^2]: For example: the sup norm is the natural one here because the Bellman operator's contraction constant is uniform over states. In a weighted $L^2$ norm the same operator has no such guarantee, which is the entire difficulty with function approximation. That did not belong in the paragraph.

## Callouts

Four kinds, each for a different job.

<Callout kind="note">
  Notes hold context that is true and useful but not part of the argument. Provenance, a version number, a caveat about which GHC this was tested against.
</Callout>

<Callout kind="idea" title="A conjecture I have not checked">
  Ideas are for the thing I suspect but have not earned. Marking them keeps me honest about the difference between a result and a hunch, which is a distinction that erodes silently if nothing is enforcing it.
</Callout>

<Callout kind="warn">
  Warnings are for the places where the obvious thing is wrong. The stopping rule in value iteration is one: testing whether successive iterates have stopped moving is not the same as testing whether you are near the fixed point, and the two differ by a factor that blows up as the discount approaches one.
</Callout>

<Callout kind="math">
  Math callouts hold a statement worth setting apart from the prose. A contraction on a complete metric space has exactly one fixed point, and iteration from any starting point converges to it geometrically.
</Callout>

## Overflow

The hard case. Long unbroken tokens have nowhere to wrap, so they either scroll, ellipsize, or push the page sideways, and only the first of those is acceptable. A URL:

https://compositionality.episciences.org/13530/pdf?utm_source=an-artificially-long-query-string&utm_medium=to-see-what-the-layout-does-when-a-token-refuses-to-break

And a line of code that runs well past any sensible column limit:

```haskell
traverseTheWholeThing :: (Applicative f) => (a -> f b) -> Tree (Either String (Maybe [a])) -> f (Tree (Either String (Maybe [b])))
traverseTheWholeThing f = traverse (traverse (traverse (traverse f)))
```

That should scroll within its own block and leave the body of the page alone.
